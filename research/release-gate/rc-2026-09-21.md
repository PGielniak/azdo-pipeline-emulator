### Line 4 was the one that needed doing rather than looking up

The L6 workflow had **never run in CI** when this walk started. `scripts/realrun.ts` had been run
locally (Azure run 553), and a local result is exactly what this line exists to rule out: an
un-dispatched workflow is a claim about CI, not evidence from it. It was dispatched with
`reuse_run: 553`, which re-reads a finished Azure run instead of queueing a new one — so the whole
CI path was validated (secrets, `pnpm build`, the extractor, the comparison, the artifact upload)
for **zero** new hosted-agent minutes. That the log shows `reusing completed run 553 (no agent
minutes)` *and* `PARITY across 13 facts.` is what makes line 4 evidence: a job that green-passed
because `ORACLE_ENABLED` gated it out, or because the script no-opped, would have looked identical
at the conclusion level.

## What this gate does **not** establish

Every line above is green. None of the following is, and a release note that omits them is
dishonest by selection.

- **L6 covers exactly one fixture.** `fixtures/e2e/01-shell-artifacts` — one pipeline shape, two
  jobs, five authored steps. L5 has four samples; L6 has one. Parity there is not parity in general,
  and the tier's value is bounded by its corpus, not by its rigour.
- **The corpus is 12 against a target of ≥ 30** (docs/06 §3). The shapes it is missing are named in
  that section and include several that a real pipeline reaches for immediately.
- **14 tasks are `[!]`** — and these are not deferred work, they are **unverified surface**. Almost
  all are "built and tested offline; one Done criterion needs a live resource". The concentration is
  what matters: **E08 deployment tasks (6)** and **E09 auth fetchers (5)** — i.e. the Azure/K8s
  deployment set that PLAN calls the priority task group, and the auth paths in front of it. E03 (2),
  E10 (1) are the rest.
- **One `VERIFY` claim is genuinely open:** C-E12-045 — whether a status function ranges over the
  *transitive* dependency closure or only direct `dependsOn`, in a chain three deep. The cell is
  doc-derived, not measured. It was recorded as unmeasurable because the oracle was believed
  unavailable; **the oracle is available** (C-E12-056), so this one is now settleable and simply has
  not been settled. C-E12-052's `VERIFY` is retracted, not open.
- **One known cosmetic defect is carried knowingly:** an unnamed step is summarised by its task GUID
  where the service shows `Checkout`/`Download` (C-E12-057, filed as **E11-S05-T03**). It changes no
  result; it does make a generated project's run summary unreadable at exactly those steps.
