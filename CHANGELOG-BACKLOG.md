- 2026-08-12 E03-S01-T01 done — DOM walker with context stack: `packages/engine/src/template/walk.ts` (`loneExpression`/`expressionUnits`/`parseDirectiveKey` for recognition, `TemplateFrame`/`rootFrame`/`childFrame`/`bindLoopVariable` for the context stack, `walkTemplate` with a per-directive-kind visitor seam), 54 tests. **Both of the task's Ground sources were insufficient, in opposite directions, and that is what set the size of this task**: the templates and template-expressions docs state *none* of the recognition rules and their one structural claim about where expressions expand is false, while the `actions/runner` object-templating engine knows exactly one directive — `TemplateConstants.cs` declares `InsertDirective = "insert"` and has no `if`/`elseif`/`else`/`each` counterpart anywhere (C-E03-115), so it is a design reference for the walk loop and for nothing about the directive set. 33 live probes (`pnpm template-walk-survey` → `research/experiments/E03-walk/`) measured the rules instead. **Directive keywords are case-sensitive** — the only such corner of a language whose names, functions and even boolean literals all fold case — and a wrongly cased keyword is not a mis-spelled directive but *not a directive at all*: `${{ IF eq(1, 1) }}` falls through to ordinary expression parsing and reports `Unexpected symbol: 'eq'` at position 4, i.e. C-E02-103's leftover-token rule applied to `IF` read as a name (C-E03-100). Directly beside it, loop-variable names *do* fold case (C-E03-107). **The finding that changed the implementation** is that directive parameters are top-level **expression units, not whitespace-split words**: `${{ else if eq(1, 1) }}` is rejected "Exactly 0 parameter(s) were expected following the directive 'else'. Actual parameter count: 2", so `eq(1, 1)` counts as one (C-E03-101, counts measured: `each` 3, `else` 0, `insert` 0). The consequence is that the `each` separator must be found by tokenizing, never by `indexOf(' in ')` — `${{ each item in split('a in b', ' in ') }}` legitimately iterates `a`,`b` and `${{ each item in split(format('{0}', in('b','b')), ',') }}` is not captured by the later `in(` either (C-E03-104); a text search gets one of those wrong **silently**, iterating the wrong collection with no error to notice. `expressionUnits` reproduces every count the service reported. Three more that shaped the API: loop variables share one **flat namespace with the contexts** and collide rather than shadow — `${{ each variables in … }}` → "The idenfifier 'variables' has already been defined within the current scope", the service's own typo preserved (C-E03-106), so `bindLoopVariable` returns a rejection instead of a nested scope; a directive is recognized only on a mapping key or a one-key sequence item, never on a scalar value (C-E03-112); and malformed-directive sentences come back from the service **without** the help link every expression error carries, which the tests assert rather than describe. **Docs correction (rule 5):** the template-expressions doc's "Expressions are only expanded for `stages`, `jobs`, `steps`, and `containers` … You can't … use an expression inside `trigger`" is false — `trigger: [${{ 'main' }}]` expands to `trigger.branches.include`, and expressions and `if` directives both expand in `pool.demands` and root `variables:` (C-E03-109). Position gating is nonetheless real, with its own sentence `A template expression is not allowed in this context`, and has exactly **one** measured member (`resources.repositories`), so it is modelled as a seam rather than a table extrapolated from the doc's list (C-E03-110). Scope line held deliberately: T01 detects, frames and accumulates (never throws — C-E02-110 hands document-wide collection to E03-S01), while `if`/`each`/`insert` semantics stay with T02/T03/T04, each of which owes committed oracle fixture pairs; the default walk is a faithful traversal that changes nothing, and `expect(result.node).toEqual(root)` is a real gate on provenance surviving the rebuild, which E03-S04-T02's provenance map depends on.
